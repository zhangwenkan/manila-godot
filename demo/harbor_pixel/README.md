# 港口 2D 像素试玩

## 当前入口与流程（2026-11-01）

- F5 从 `character_preview/character_select_preview.tscn` 选角开始；确认后进入本目录的港口。F6 仍可直接运行港口，默认使用卡门。
- 每航竞拍港务局长 → 得标者买一股或跳过 → 点货物、点船装载 → 安排 0–5 且合计 9 的起点 → 派遣 → 三次投骰 → 结算。只有当任局长可以准备和投骰，两个 AI 走同一规则接口与骰盘动画。
- 准备是自动衔接的一次性阶段，没有常驻“准备船队”或“股票买入”入口。岗位仅在选中后显示局部确认卡；规则通过 `?` 按需查看。
- 投骰直接点击底图右下蓝色骰子图标（1448×1086 棋盘中的 `Rect2(1324,955,110,113)`），复用原 3D 货物骰与木托盘。
- 真人固定为玩家 0，所选角色的名字、头像、现金、船员和手牌保持一致，不随局长易主切成对手数据。
- 试玩约定：首航玩家 0 先竞价，全弃同序重拍；后续由前任先竞价，全弃留任。出价受现金约束；未实现贷款、角色技能和完整海盗/引航决策。
- 共享手牌组件已迁至 `ui/stock_hand.gd`。旧场景清理尚被执行权限阻止，旧目录当前仍在，不能将其视为已删除。
- 新增 `tools/harbor_entry_check.gd` 检查六角色真实确认跳转；规则与交互分别运行 `harbor_pixel_rules_check.gd`、`harbor_pixel_demo_check.gd`。入口限时 60 秒、港口整合限时 150 秒；必须同时检查完成标记、失败计数、脚本错误和退出码，历史通过记录不代表当前版本。

## 以下为旧版设计与验证记录

以下保留来源与美术历史；其中固定局长、常驻行动簿、旧 F5 入口、准备按钮等描述已由上面的新流程取代，不能用作当前操作指南。


这是一个独立的、可从准备阶段玩到最终排名的三航程 Demo。港口棋盘、货船、派遣岗位、股份行情和操作界面使用原生 Godot 2D；投骰例外，复用原项目的全屏遮罩、3D 货物骰和木托盘（独立 SubViewport），并非把港口改回 3D。

原项目的主场景、HD-2D 实验和 3D 资源保持不变。本目录尚不是完整版规则的替代品。

## 启动

需要 Godot 4.6.x。

1. 用 Godot 导入仓库根目录的 `project.godot`。
2. 打开 `demo/harbor_pixel/harbor_demo.tscn`。
3. 按 **F6（运行当前场景）**。F5 仍启动原项目主场景。

也可以在仓库根目录用终端启动。下面的 `godot` 指 Godot 4.6 可执行程序；如果未加入 PATH，请替换为程序的完整路径：

```sh
godot --path . res://demo/harbor_pixel/harbor_demo.tscn
```

画面按 4:3 港口构图等比缩放，其他窗口比例保留留边；不拉伸棋盘。小窗口仍可交互，但建议至少 1280×960，以便阅读中文文字。

## 怎么玩

- **准备**：你固定担任港务长。右下 **股票买入** 打开独立窗口，列出银行余量、买入价与不可购买原因；每航程可选购一张，也可以不买。右侧 **SHARES** 只显示四种货物的公共股票价值，没有购买操作。点击“装船 / 启航”，选择三种不同货物；三个起点各为 0–5，合计必须为 9。默认配置可直接确认。
- **派遣**：你和两名电脑依次派一人。直接点击船座或岸上场景岗位，在左下说明区确认。选择岗位不会扣费；确认成功才扣费、消耗船员。**修船厂使用更新场景中已有的三个工人，不再叠画 Izezia 或通用小人；合法空位脚底显示现有旋转漩涡光带，头顶显示放置费用：左侧 `$4`、下方 `$3`、右侧 `$2`。** 点击人物、光圈或费用都可选择对应岗位，悬停/选中只增强光圈亮度；确认后隐藏光圈与费用，在脚底显示玩家归属短色标，背景人物保持不变。其他岗位仍为局部轻微提亮，悬停/键盘聚焦显示细边、半透明通用小人与费用，确认后显示玩家色实体小人。非法岗位仍可查看费用和限制原因，但不显示可派预览。
- **灯塔领航员**：直接点击灯塔建筑，不再另盖岗位板。当前按原图轮廓大小，将左侧较高的灯塔对应大领航员（5 比索、推进 2 格），右侧较矮的对应小领航员（2 比索、推进 1 格）。建筑局部提亮，预览 / 实体小人站在塔脚，费用仅在交互时显示在小人旁。整座建筑仍可点击；鼠标与键盘都使用场景细轮廓反馈，不再画整楼矩形焦点框。选中优先于键盘焦点，键盘优先于鼠标，只保留一个活动预览。
- **航行**：前两轮派遣结束后首次投骰；第三、四轮派遣分别接第二、第三次投骰。点击“投掷货物骰”，打开原版全屏遮罩和木托盘，每条船使用对应货物颜色的物理骰。三骰全部落定后才提交一次航行结果，停留约 0.8 秒再收盘推船。电脑自动行动，不需要替电脑操作。
- **放弃派遣**：“结束本航程派遣”需要确认。确认后放弃这一航程剩余的派遣机会，已派出的小人保留；下个航程重新获得四名船员。
- **结算**：第三次航行后显示收益。较长明细在“完整账本”中翻页查看。确认结算进入下个航程；第三航程结算后进入最终身家排名。
- **回合进度**：顶部原 `TURN 1` 位置由代码绘制深棕像素木牌，上行显示 `TURN 当前航程 / 最大航程`，下行显示准备、派遣轮次与当前玩家，或航行次数与投骰 / 落定 / 前进状态。旧青绿色回合面板已删除；右下仅保留操作提示与按钮，不再重复显示当前玩家等待和航行状态。
- **角色状态**：左上角使用原图位置的浅色头像框与两块深棕数值牌，上牌金币图标显示你的现金，下牌船员图标显示你的可用船员。数据随买股、派遣、结算和重开同步；电脑行动时不会切换成电脑的资源。旧大青绿色角色面板已删除。
- **看信息**：右上“玩家 / 记录”查看三人的现金、可用船员及完整日志；“?” 打开规则。原图 SHARES 区展示公共市价；底部以正面扇形卡牌展示你实际持有的股票，每张股票对应一张卡，同种股票逐张显示，买入或重开后同步更新。不再用持股数量文字代替卡牌，也不需要点击翻面。

### 键盘

| 按键 | 操作 |
| --- | --- |
| 空格 | 当前可航行时投骰；已选岗位时确认；骰子落定后收盘；船只移动时跳过移动 |
| Esc | 关闭弹窗、取消选择；骰子落定后收盘；船只移动时跳过移动 |
| Tab / Shift+Tab | 顺序 / 逆序选择可交互目标 |
| Enter | 激活键盘选中的目标 |

骰子仍在物理滚动时，关闭按钮及空格 / Esc 均不收盘；落定后可用 ×、空格、Esc 或 Enter 提前收盘并开始推船。跳过船只移动不会再掷骰或重复结算。整个骰盘与推船期间暂停 AI、隔离棋盘输入。投掷超过 25 秒未落定，或投掷中调整窗口尺寸，本次不结算并释放骰盘，可重新投掷；已经落定的结果不会回滚。正常收盘保留已落定的舞台供下次复用，隐藏期间冻结骰子并关闭处理与视口渲染；未完成的投掷取消后则销毁舞台，避免旧物理状态或回调进入重试。

## 本试玩的规则

- 三位玩家各以 **30 比索、4 名船员、2 张随机股票** 开局。每种货物共五张股票，开局发出的股票从库存扣除。
- 每航程仅你可以在准备阶段买一张股票，价格为 `max(5, 当前市价)`；库存不足或现金不足不能买。
- 货物为人参、肉豆蔻、丝绸、玉石，对应整船分红 **18 / 24 / 30 / 36**。船上小人按人数平分、向下取整，同一玩家派多人可领多份。
- 货船必须先填最便宜的空座。已到港船不能继续派遣；到港后不再移动。
- 正常航行越过 13 格即到港。第三次航行结束恰好停在 13 格时，没有海盗则正常到港，有海盗则触发下述简化劫掠。
- 港口和修船厂按照到港数 / 受损数依次启用 A、B、C 泊位。占用启用泊位的小人获得 **6 / 8 / 15** 比索；派遣费用是另一项支出。
- 保险岗位派遣时立即领取 **10**，结算时赔付所有启用的修船泊位金额（含无人派驻泊位），不会再领一次 10。先结算收入再扣保险责任。
- 到港货物的市价沿 **0 → 5 → 10 → 20 → 30** 上升一档。股票不另行派息，按结束时市价计入身家。
- 三航程结束，或任意货物市价达 30，确认当航结算后终局。按 **现金 + 持股市值** 排名，同分并列。

### 原版买股规则核对

2026-10-15 查阅 [UltraBoardGames 的 Manila 规则转录](https://www.ultraboardgames.com/manila/game-rules.php)：港务长在竞拍结束后、选择货物及摆船前，可以从银行买一张股票；按当前市价支付，最低 5 比索。不买也能继续装船。本试玩将此环节放在准备阶段，固定玩家为港务长，仍由规则模型检查限购、现金和库存。

同一转录还记载股票抵押：每张未抵押股票可借 12 比索，偿还 15 比索赎回，未偿还贷款在最终计分时每笔扣 15。本次没有新增抵押、贷款、拍卖或卖股界面；该规则文本没有描述主动卖股或玩家间股票交易流程，不据此断言所有版本都禁止交易。未取得出版社规则书，以上来源是二手规则转录；本试玩的完整市价阶梯仍按下述简化规则，不把未核实的全部细节标为原版规则。

### 原版岗位数量核对

2026-10-15 对照 [UltraBoardGames](https://www.ultraboardgames.com/manila/game-rules.php) 与 [RulesPal 的 2005 版规则文本](https://www.rulespal.com/manila/rulebook)：玉石有4座，其他货物各3座；每航程只装三种货物。岸上为港口3、修船厂3、海盗2、领航员2、保险1，共11位，因此每航程共20或21位。当前目录和点击目标已包含这些位置，原来的显示缺口是两座灯塔没有常驻费用标识，并不是缺少领航员规则入口。默认首次人类派遣时仅13位合法：三船各最便宜一座、港口和修船厂各3、海盗船长、两个领航员、保险；其他座位仍保留场景点击入口供查看。

本次没有取得出版社原始 PDF，在线正文不能独立验证所有印在棋盘/货物图中的费用，因此费用仍取项目既有岗位目录，不声称全部印刷数值已逐项核实。保险 `$0` 是派遣费，现有 `+10` 是立即领取金额；港口 / 修船厂 `6 / 8 / 15` 是收益，不是费用。原版领航有前后移动及大领航分配两船的选择、海盗有第二航登船等机制，本试玩仍保留下列简化，不因位置数量完整而声称完整实现原规则。

### 明确省略或简化

- 固定你为港务长，不竞拍；没有贷款、股票抵押、贫困免费派遣、角色技能及多人联机。
- 小 / 大引航员在第三次航行前自动把一条有己方船员且尚未到港的船向前移动 1 / 2 格；按预期收益选船，不预看骰子。没有目标则放弃，不提供手动前后调整。
- 海盗第二次航行不登船，留守至第三次航行；劫掠恰好停在 13 格的货船，海盗小人均分货物收益，原船员无分红。劫掠船自动送港，不提供送港 / 送修选择。
- 保险现金不足时由银行补足，不产生负现金或债务。
- AI 只做合法派遣或放弃，不竞拍、不买股，不代表完整版策略。

## 美术边界

当前背景是用户更新场景的适配副本 `harbor_workers_board.png`（1448×1086）。新原件另存为 `harbor_workers_reference.png`（1456×1088），未修改原件；特征点配准支持整幅尺寸映射，适配副本仅用最近邻缩放到既有棋盘坐标，不局部移动三名工人。旧 `reference.png` 与 `harbor_board.png` 继续保留且逐像素一致；原 `build_art.py` 仍只重建旧资源，不会覆盖新图。为避免实际手牌后露出假牌，额外使用透明 `fan_patch.png`，仅在原静态扇形轮廓内以本地 OpenCV 修补恢复底色；不重绘整块海面或另盖 HUD 底板。原图扇形尖端在 y≈899 已出现，因此原下方海面保护矩形中这部分手牌不再要求像素不变；y<899 的开阔海面、灯塔、刻度仍受保护。货物图标、头像和股票正面来自本仓库，没有上传图片或调用外部生成服务。

实时船体、货物与座位共用同一坐标，包围范围约为 64×89；取消大阴影、尾流和船名底板，两侧原数字刻度留空。底部复用 HD-2D 的扇形组件和 `stock/*.webp` 正面，使用独立的只展示模式，不影响旧 Demo 默认的私密翻牌行为。卡牌以实际张数左右展开、轻微旋转，显示区约为 `(408,926)–(1072,1086)`；不添加持股文字、并排牌或持股底板。

除下述修船厂旋转漩涡光带试验外，`placement_marker.gd` 使用场景局部半透明暖色提亮，保留下层建筑 / 木板纹理。两座灯塔使用独立的阶梯状塔身轮廓；其他岸位为各自地面局部多边形，船座为甲板局部。默认强度4.5%，活动位置12%并加1像素细边，不随时间闪烁。活动合法空位显示48%透明度玩家色小人，费用单独放旁边；确认后由 `owners` 决定实体小人。岸边小人为7×10像素图标的3倍，船座为1倍，带1像素暗投影。场景轮廓、脚点、小人和费用与输入几何分离，船上新增绘制保持64×89船体范围，岸位与整座灯塔原命中不变。弹窗、骰盘或忙碌时不展示场景预览；非法位置可查看费用但不误提示能派遣。原背景不修改，灯塔以明确的阶梯塔身分段作为局部高亮掩码，保留掩码之外的海面、刻度和场景像素检查。轮廓来自现有场景坐标的代码近似，未完成逐像素美术分层或人工贴合验收。

SHARES 不再覆盖重画标题、木框，也不再显示货物名称、图标或数字行。按用户指出的原图缺陷，`shares_patch.png` 将内部红 / 蓝 / 黄 / 绿四列统一为 **41 像素宽、等间距**，各格彩色内区宽 36 像素，黄色不再被绿色挤占。四列共用原图未遮挡格子的纹理和分隔线尺寸，保留六条格带的高度与轻微透视偏移；只在内部覆盖修正，不修改保留的原图文件和外侧标题、木框。`shares_discs.png` 沿用提取的圆块轮廓、明暗和四色，圆块同步居中于新列；颜色绑定为红色肉豆蔻、蓝色丝绸、黄色人参、绿色玉石，同价时等距分列，不互相遮挡。没有买入费用、银行余量、购买状态或个人持仓，也不注册任何鼠标 / 键盘命中区；买股不会改变行情。

## 文件分工

- `harbor_demo.tscn`：单独启动入口。
- `harbor_demo.gd`：2D 绘制、命中区域、鼠标键盘、动画及电脑行动节拍。
- `dice_overlay.gd`：全屏骰盘生命周期、遮罩、结果回调与超时；复用 `../../dice3d/dice_stage_3d.tscn`，不修改原骰子物理代码。
- `shares_board.gd`：只读公共股票价值板，在原图格子上按市价定位四色圆块；不绘制货物文字、数字行或新木框，不依赖持仓、库存或购买状态。
- `placement_marker.gd`：修船厂旋转漩涡光带、头顶费用与归属短标，以及其他岗位的场景高亮/通用小人；不负责命中或规则。
- `character_status.gd`：原图左上头像框与两块数值牌的代码绘制；只读显示你的现金 / 可用船员，替代旧大角色面板。
- `turn_board.gd`：原图顶部 TURN 样式的代码绘制与只读回合 / 阶段状态，替代旧中央进度面板。
- `action_style.gd`：行动区与独立买股弹窗共用木框纸面和按钮绘制，不影响其他 HUD。
- `harbor_game.gd`：同步规则模型；所有花钱、派人、买股和结算均由模型校验。
- `build_art.py` 与 `art/`：本地生成脚本、参考底图和图标。
- `build_workers.py`：保留用户更新的三工人场景原件，校验指纹并用最近邻生成当前棋盘适配副本。
- `build_izezia.py`：历史试验的透明人物构建工具，保留但当前场景不再加载该人物。
- `../../ui/placement_state.gd`：复用原项目岗位目录与占位约束，未改动。
- `../../tools/harbor_pixel_rules_check.gd`、`../../tools/harbor_pixel_demo_check.gd`：规则与交互检查。
