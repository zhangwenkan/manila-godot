# 微缩港湾 / HD-2D Demo

用于比较「单屏全局派遣 → 近船航行 → 返回全局」的独立视觉交互样片。**当前已接入 R2.1 完整重建的像素保险码头**，替代 Demo 中第五轮保险资产；保留「观察吊机」的滚轮缩放、右键环绕与 Esc 返回，以及原派遣、航行和第四轮仓库／修船棚。**视觉核对未完成，不是已经还原参考图的完成版本。**

不替换正式主场景，不读取或写入正式存档，不接入正式派遣轮次或推进正式 UI-05。复用工程内头像、股票卡、像素字体和岗位规则；其余港口、船体、水面及像素图集在本地程序化构建。

## 运行

Godot 4.6：打开 [harbor_demo.tscn](harbor_demo.tscn)，按 **F6（运行当前场景）**。F5 仍然运行原游戏。

也可在工程根目录运行（`godot` 替换为本机 Godot 可执行文件）：

```sh
godot --path . res://demo/harbor_hd2d/harbor_demo.tscn
```

正常入口是手动交互窗口，不会自动关闭。需要限时自动巡演时使用下方验证脚本。

## 操作

| 操作 | 效果 |
| --- | --- |
| 点击甲板或岸边的圆形岗位 | 右下显示费用、说明或不可用原因；选择不扣费 |
| 点击「确认」 | 扣除该角色现金与一名伙计，在岗位放置标记；保险立即领取 10 比索 |
| 点击左下角色名字 | 同步切换头像、现金、伙计和整套个人持股；手牌盖回 |
| 点击底部股票卡；或聚焦后按 Enter | 翻开／盖回该张卡，不派遣、不扣费 |
| 悬停或聚焦股票卡 | 抬起该卡；重叠卡的绘制和命中顺序同步 |
| 点击「掷骰 · 航行」或 Space | 三枚货色骰子给出结果；三船同时推进，默认短暂切至船侧后方近景 |
| 点击「跳过 / 回全局」或 Esc | 航行中立即结束表现、回到全局；不重复推进或扣费 |
| 点击右上「观察吊机」 | 进入吊机近景，隐藏派遣、角色与手牌 UI；航行中不可进入 |
| 观察中滚动滚轮 | 向上放大、向下缩小；只在 3D 画面区生效 |
| 观察中按住右键拖动 | 绕吊机旋转；上下拖动改变俯仰角，角度有上下限 |
| 观察中点击「返回全局 [Esc]」或按 Esc | 恢复全局与原岗位选择，游戏进度不变，手牌保持盖回 |
| 非航行、非观察时按 Esc | 取消岗位选择 |
| 右上展开工具区 | 显示默认收起的四个演示开关 |
| 工具区「自动近景」 | 关闭后保持全局镜头播放航行 |
| 工具区「像素」 | 切换 2× 最近邻放大与 1× 原清晰度；外层中文 HUD 不降分辨率 |
| 工具区「分散船位」 | 清空本次演示并把三船放至 0、7、13，检查单屏布局 |
| 工具区「重新开始」 | 清空派遣和资源变更，恢复示例船位 1、4、7 |

手牌默认背面；切换角色、重置、失去窗口焦点或航行收起时全部盖回。这只是同屏展示保护，不是联网隐私或权限隔离。手牌底缘有意裁切；悬停／聚焦会抬起。两位示例角色各持三张真实股票卡，不为凑满扇形额外增加持股。

全局显示全部航道和岗位；航行近景隐藏岗位按钮、区域名称和手牌，左侧保留三船状态。原全局／航行镜头保持固定方向；另有可旋转的吊机观察模式。三种视图复用同一个正交相机和同一座 3D 港口，不是替换图片或复制一个展示模型。

观察中不能派遣、切换角色或掷骰，Space／Enter 不会触发玩法。退出不改变现金、伙计、持股、船位、回合或之前选中的岗位；翻开的手牌会盖回，不会自动重新翻开。右键在画面外释放、窗口失焦、退出或重置都会终止拖动，鼠标不被捕获。

## 画面与布局

- 有土地厚度的棋盘底座，蓝色海面、浅青近岸、沙滩与草地。

- 共用布局描述，根据内容尺寸调整世界取景与 UI。覆盖 4:3、16:9；窄于 4:3 的画幅未专门适配。

## 本地图集

[art/harbor_atlas.png](art/harbor_atlas.png) 是 256×256 的 4×4 像素图集，各格 64×64，含 60×60 内部纹理与 2 像素边缘延展。材质使用显式 UV、最近邻采样，在格内重复，静态网格按实际材质和 UV 合批。

16 格依次为：木板、棕瓦、灰绿瓦、蓝绿墙、土黄墙、石面、草地、沙地、深木、货箱、炭灰瓦、纸面、叶片、红漆、船壳、帆布。

本地制作源是 [art/build_atlas.py](art/build_atlas.py)，需要 Python 和 Pillow。游戏运行本身不依赖 Python。重建命令：

```sh
python demo/harbor_hd2d/art/build_atlas.py
```

脚本使用固定随机种子，校验重复生成的像素一致及各格边缘延展。未调用外部素材或图像生成服务，也未上传用户参考图。

## 范围与简化

- 21 个岗位复用 [PlacementState](../../ui/placement_state.gd) 的费用、船位低价优先、海盗船长优先和到港限制。
- 两位角色是独立临时数据，各有 30 比索、5 名伙计和三张示例持股。个人手牌由结构化货物 ID 生成。
- 航程恰好 13 不算到港，超过 13 才到港；已到港船不会继续推进或接受新派遣。
- 没有实现正式派遣轮次、海盗执行、引航改位、分红、保险最终赔付和完整结算。
- 骰子是结果提示，不是物理滚骰；公共行情是明确标记的固定示例，不与正式市场联动。
- 美术是程序化样片，不是概念图的最终精修版本；未进行帧率、帧时间或显存基准测试。

## 验证

逻辑和输入路由检查（无需 GUI）：

```sh
godot --headless --path . --script res://tools/harbor_demo_check.gd
```

真实窗口限时巡演、截图并退出：

```sh
godot --path . --script res://tools/harbor_demo_check.gd -- --preview
```

- 60 秒 watchdog；结束输出 `HARBOR_DEMO_PASS` 或 `HARBOR_DEMO_FAIL`，退出码分别为 0 或 1。
- 检查派遣校验、资源隔离、保险、重复确认、非法骰子、到港、跳过，以及三船结果只提交一次。
- 输入检查将鼠标、键盘事件送入根视口，验证岗位命中、确认、整套角色切换、工具区展开、像素倍率和跳过；确认按钮有焦点时 Space 只掷骰、不扣费。**不是操作系统级输入自动化。**
- 手牌检查包含数量与货物 ID、默认及换人／重置／失焦／收起盖回、旋转卡片命中、绘制与命中顺序、悬停／聚焦抬起、键盘翻牌以及翻牌不派遣。
- 吊机观察检查包含入口点击、滚轮单次缩放与上下限、右键环绕与俯仰限制、画面外释放／失焦／退出／重置清理拖动；对比观察前后完整玩法状态，验证观察中禁止派遣与掷骰、航行中禁止进入观察、返回后普通按钮仍可点击。
- 画幅检查实际改变根内容尺寸为 1600×1200 和 2048×1152，不是把固定 16:9 塞入 4:3 窗口。检查投影、按钮互不重叠、甲板命中和岗位避开抬起手牌区域；另检查两种像素倍率的吊机初始入镜，以及观察中改尺寸再返回全局。
- 到港几何检查使用实际船网格包围盒，检查船继续向前但不伸入横向栈桥；不等同于完整碰撞或视觉验收。
