## 结论与依据

建议海盗岛继续独立在外海侧，向13事件水域靠近一部分；右岸终点附近优先预留修船厂。正式方案试作可从岛中心Godot(-17.5,0,-14)、洞口总yaw +10°开始，即当前中心Z前移8m、当前yaw -20°转+30°。洞口保持可见的斜正面，短出击栈桥另外朝航道组织，不强求整座洞山完全正对运输船。

当前三条13船位约X=-7.4/-3/1.4、Z=-7.85；旧岛中心Z=-22，比13更靠终点约14.15m。实际相机以当前关注船/本轮subject进度取景，切到落后船就不会继续保留岛。第一组75状态/8图显示旧岛在全船10.5时投影包围框入屏0%，11.5约8.9%，12约41.5%；[8,10.5,13]关注前两船时仍0%。这些是包围框与屏幕相交比例，不是渲染像素面积或遮挡率。上轮13同步/全部到港成功不能覆盖这些状态。

三个方向的试验：

- 直接搬至(-18,0,-8)：过于前置，+35°时13画面仅约84%包围框入屏、到港61%；转到+60°洞口近侧面，到港转背。不能仅把岛移到13正旁边。
- 右岸(11,0,-10)：较容易保持入镜，但岛压进约1.3m院地、现小码头和植物，成为需要重建的嵌岸洞寨，并占用未来修船厂候选岸段。
- 折中(-17.5,0,-14)、+10°：现镜头p12仍裁、p13全入、到港底部裁。临时末段构图从11.5提前使用终点取景，13/到港相对当前targetZ+3、offsetZ+2，FOV48不变，11.5/12/13/到港均有20px以上整岛边距。三张实拍洞口和骷髅可读。不过到港船体显示高度约110–122px，较原构图小约9–12%；尚未形成所有关注模式/动画平滑/可读阈值验收。不能据此全程替换普通镜头。

建议普通航行保持既有跟船尺度，在靠近13时渐入终点/海盗水域；实际事件锁定涉事船和出击点，按需要纳入多个合法目标。用户手动关注落后船时仍应允许看那条船，不能用“岛永远在屏幕内”迫使镜头无限拉远。过渡、目标选择、动画及点击可读性应在正式实施时一起验证。
