# 下层沿岸实体地形控制方案

本文件与 `structure_lower_plan.json` 是供实际建模的控制建议，不代表完成实施或视觉验收。基于本轮 `terrain_structure_20261123/baseline.npz`、`objects_before.json` 和只读下岸审查；坐标使用 Godot 米制，路线点为 `[x,z,height]`。

下层公共路沿贸易行—Sea Breeze—鱼摊—酒吧—餐厅—杂货店连续组织。路线控制包含路面纵坡、横向宽度与接草肩，不能只把同样的路径形状换一种颜色。共同路口合并成一个路床，再从实际地表生成磨损中心、根草边缘和局部露土。门前短入口从公共路接到现有最低一级台阶前，较高的台阶承托优先于低院地的平均高程。

贸易行至 Sea Breeze 一带主路中心大多在 x13，院地居内，外侧留宽草岸向沙地下降。Sea Breeze 的两组桌椅移入建筑南北侧的小院，避免道路绕着每一把椅子扭曲。鱼摊旁主路收至 x11.8，摊位最外柱与路肩需在实际视图中核对，必要时整组向内移动。

酒吧的高木廊前缘约在 x10.74..11.24，z38.5..43.1；最低石阶底高1.875m。保留建筑后，无法在这里同时放下宽公共路和宽缓草坡。方案把路中心置于 x9.98..10.2、高约1.65m，并只在 z38..42.7保留一段有实际承托作用的短切坡。岩土坡脚、短岩肩和草冠应形成有起伏的局部体块，不能把它延伸为全岸灰墙。酒吧—餐厅转角的整棵棕榈移到 x10.25,z44.9。

餐厅与杂货店之间必须真正填出连接台地。现有 x13,z53 高约0.311m，规划共同鞍台为1.16m，需填约0.85m。台地连接两院并容纳侧面桌椅和供应杂物；靠海外沿仍是接沙滩的草岸，不再留插入两楼之间的沙舌。餐厅北侧杂物转移到鞍台内侧，北侧座位区避免与箱堆重叠。

主要下海口只保留两处：贸易行 z9 码头和酒吧北侧通往 z38作业码头的斜坡。后者从 `[12,34.8,1.37]` 下到 `[8.6,38,0.35]`；z38与z43两个作业码头沿低沙滩互通，不再各画一条独立深色道路。沙滩和海床原高程不高于0.25m的部分固定，岸脚控制点只引导其上方的草岸接合。

JSON共含11条路线、7片院地或鞍台、24条岸坡断面及10条整组迁移建议。岸坡断面是手工控制建议，尚未完成逐点新网格验证；实施时按低地保护规则融合，不可据此声称全部接触检查已通过。宽草岸也不能统一成平行等宽色带：道路、院地和现有低沙地决定其实际宽度，坡冠和坡脚分别设计。

楼板、木廊、台阶和基础保持原几何及支撑关系。各入口在最低一级台阶外缘前停止，阶下原有实际承托点优先。物件迁移按完整语义组确认，包含椅腿、牌架、整棵植物及附属件，不用宽松包围盒一并拖动建筑零件。坡脚石块在新岸坡完成后重新嵌入；沙面自身不因石块移动而改变。

完成实体起伏后，先看正常游戏机位的路床连续性、草岸宽度、台阶接地和两处下海口，再确定表面质感。岩壁规整、道路断头和交叉是否解决应以新图判断，模型完整性与检查通过不能替代视觉评价。
