## 共同问题

浅褐色理论上表示压实路面／院地，深黄褐表示裸土坡，淡黄表示沙滩。但目前同一条通路遇到坡形时，常变成浅褐面覆盖坡顶或坡侧、淡沙从低处切入、草沿在两者间留下狭条；三种颜色没有稳定地对应“走在哪一层、从哪里下坡、走向哪个入口”。浅褐色已连成一片，也可能只是把路面颜色延伸到了没有相应路肩的坡上。

沿岸还重复着“平顶草台—连续裸土侧带—平沙滩”，路面在草台上绕房屋布置，码头在低沙地上独立结束。楼前平面、通路坡度、岸边降高和码头落脚没有一起组织。局部扩路、删草岛和淡化边界只能改变色块形状，不能解释这些断层。

下表的世界范围是根据 `occupancy.json` 路线端点及画面位置推定的 **Godot X/Z 大致范围**，供后续定位；没有逐点反投影，不得当作精确施工边界。植物和石头是否实际侵入碰撞通道没有新测量，表中“挤压／阻挡”描述画面的可读通行空间。

## 后续设计应先回答的关系

这次是审查，没有批准新造型或进行试改。下一步应把整段下层岸地放在同一张结构图上，先确定连续沿岸步行面、每栋门前院地和通往码头／沙滩的有限几个下降口，再共同确定坡冠、坡脚、草肩与岸石位置。供货树／箱桶／网架随后留出对应使用空间。只有这些形状能解释人在何处行走、为何转弯、如何下降，才分配浅路、坡土、沙与草；不能继续以“路径权重连续”替代道路设计，也不能用混色模糊掉陡坡与平路的冲突。

本复查未测量坡度、净宽或碰撞，没有确认任何物件真实悬空，也没有证明所有材质边界都存在网格裂口。确定的是最终实机画面的空间解释仍不成立；应与上层岩壁／医院的独立复查一起汇总，不能仅修本表的几个色块端点。
