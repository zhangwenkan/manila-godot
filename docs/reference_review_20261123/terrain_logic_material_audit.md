# 最终 road23 地形／材质关系只读诊断（2026-11-23）

本次未启动 Blender/Godot，未改运行资产、历史制作脚本或源场景。读取最终 `road_contacts_20261123/land_data.npz`、`grade_before_after.npz`、`occupancy.json`、原控制制作脚本和真实 `terrain.glb`，结合用户再次否定的医院／贸易行图及最终 market、north、civic、landward 图定位。结论不沿用上一轮中心线连续的“通过”作为视觉标准。

**核心问题是通行地面与坡体没有被共同设计。** 多次处理依次叠加：保护旧接地点的局部地形变形、独立草舌／沙湾解析遮罩、按折线距离铺路、按全局高度／平滑法线减路、最后仅在三个矩形中换规则。道路中心可以连通，但同一条路的横向宽度仍压在草唇、坡肩、陡坎上。草地、沙口与院地各自的边界在同一位置相交，实际图里才会出现窄草楔、土色横带、尖角和像被截断的路口。

## 方法与边界

- `terrain_logic_material_audit.py` 对最终真实三角面建立空间查询；由平面梯度计算实际面坡、相对路线方向的纵坡和横坡，独立验证导出 GLB 与 grade 三角一致。
- 所有 16 条 route 沿程不超过 0.12m 取样，每站覆盖名义半宽 1.25 倍内的 21 个横向点；6 区另作 0.1m 网格扫描，以实际最终路通道领先区域定位。
- `land_data.normal` 是插值顶点法线的 Y 分量。报告中的 `occupancy_interpolated_normal_y_angle_deg` 仅为 `acos(normal.y)` 的角度指标，**不是物理面坡，也不是重建最终像素法线**。它与真实面坡的差异恰好说明不能用它判定路床。
- 30°／45°分档只是搜寻候选点，不是视觉、可走性或任何规范验收线。统计没有遮挡剔除，建筑下与货港开挖附近不能仅凭数字宣布存在可见缺陷。
- 输出 `terrain_logic_material_audit.json` 保存原始定位、横断面与全部路线；`visual_acceptance=false`，没有生成“视觉通过”。

## 为什么规则直角／硬交点会反复出现

1. **地形和地类使用不同控制。** `ground23_10_stronger_forms.py` 的沙湾形体受建筑／道具固定点、防折叠回退和既有地形约束；`ground23_03_land_use.py` 后续独立使用 Gaussian、带状解析湾口与草舌，并非从最终真实坡脚／冠线提取边界。局部形体未能达到目标时，材质仍按目标形状覆盖。
2. **旧规则把材质身份绑定到高度或平滑法线。** G23 路权重末尾统一乘 `ss(.48,.76,normal)*ss(.25,.65,height)`，同时再被湾口和沙嘴削弱。它既能在平坦低地抹掉路线，也能在平滑法线不足以反映陡面时留下道路。
3. **新规则只在矩形作用域内取消裁路。** trade、grill、clinic 三个 axis-aligned scope 及另一个 `soil_scope` 形成局部换规则边界；范围外 diner/sari/school 沿用旧算法。四邻域填底只是扩散邻材质，未重新判断“这是草肩、坡土还是沙地”。这些范围本身不能证明每个可见直角都是矩形接缝，但确定会产生多套边界相遇的条件。
4. **路带并集没有表达路口与地床。** 折线距带和院地多边形直接 `max` 合并，不计算路宽横断面。内弯、门前路口、途经坡肩会自动合为大片棕色；面积连上不等于空间关系正确。
5. **着色器把错误轮廓显示得更清楚。** `landform_mass.gdshader` 只保留距领先权重0.28以内的竞争地类，再归一；草边还有高度扰动。它能减少透明混色，却无法修正错误接触线，且五种高度图都只改法线、不会形成坡脚／道路凹槽／草根层。

建议下一轮按“完整场地单元”处理：贸易行湾口—Grill共同低路、医院平台—回折坡路、Tavern—Diner—Sari共同来路、学校台地分别先设计地面高差和可用空间，跨区接头一起确定。材料边界从这些实际形体关系导出并做局部艺术调整，不再按独立矩形、全局高度或单独的道路中心线补洞。本报告属于原因诊断，未实施上述重建。
