## 在另一台 Windows 电脑上接续

1. 解压 `01-resume-core.zip` 到一个新的本地目录，保持里面的目录结构。运行根目录 `open_project.ps1`，使用随包 Godot 打开根工程。核心包带可重建的资源导入缓存以减少首次纹理压缩等待；GPU 着色器缓存会在新机重建。需要先看场景时不需要联网安装 Python 包。若缓存被清除，先等待编辑器完成导入再运行截图脚本，全项目首次压缩可能超过两分钟。
2. 打开该目录内 `manila-godot` 为 Codex 项目，新建聊天，粘贴包里的 `resume_prompt.txt`。登录/供应商凭据需在新电脑重新配置，不随包保存。
3. 需要建模或截图工具时运行根目录 `setup_tools.ps1`：用随包 Python 创建新的环境，并从随包 wheelhouse 安装依赖。Blender、Python、MCP 源与港口技能均已备份；不要照搬旧虚拟环境。需要 MCP 的终端中执行 `. .\setup_tools.ps1 -StartReferenceBlender`，点加空格表示在当前终端加载环境变量；脚本核对端口后只启动保存的新源，后续仍须核对实际 PID 和文件。
4. 需要完整历史图/视频/模型备份时，把 `02-history-materials.zip` 解压到同一目录。最新最终图已在核心包，不必等大包才开始讨论。
5. 需要 Git 历史和原 staged 状态时，安装 Git 后运行根目录 `restore_git.ps1`。它只允许目标还没有 `.git` 时运行；通过 bundle 恢复分支/提交，并把 staged 补丁应用到索引。工作区现状以快照为准，不执行 hard reset。
6. 可运行 `runtime/python/python.exe verify_package.py` 检查已解压文件的 SHA-256。只有核心包时会提示可选历史素材未解压。

包里的 PowerShell 脚本可以右键“使用 PowerShell 运行”。若执行策略阻止，终端运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\open_project.ps1`（或对应脚本），不会永久修改系统策略。

## 导出覆盖范围与限制

这份包用于可靠接续：文件、约束、进度和可查聊天能被新聊天读取。它不承诺把旧会话自动导入新 Codex 的侧栏，也不保留服务端上下文缓存。当前工具没有提供可验证的完整聊天导入操作，禁止覆盖新机器的 Codex 数据库去碰运气。

导出范围是本机能找到的项目会话（含旧 cwd、子代理、归档记录、现存 rollout 与历史数据库）。部分早期原始 rollout 已缺失，结构化记录仍在；仅有用户消息/无回答的会话会在覆盖报告中明确标注。不能把缺失原始日志说成已恢复，也不能保证远端或已经永久删除的消息被找回。当前导出聊天以生成时刻为截止，之后的消息需再次导出。

不复制 `auth.json`、API 密钥、浏览器登录、全账户数据库或其他项目聊天。聊天记录可能含用户私密内容，包放在项目外，供本人私下搬运，不提交 GitHub。

再次导出：在工程根目录运行 `python tools/handoff/export_codex_handoff.py`。工具自动生成新目录，不覆盖上一份备份。输出清单记录每个文件的归属、大小、SHA-256、会话覆盖和排除项。
