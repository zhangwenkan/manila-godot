## 前三段实际教会了什么

### 先改能说清的问题，再补局部信息

神龛片头直接展示 V3，随后回放早期版本；鱼摊和灌木也先给完成预览。不能按时间顺序误判成“精细成品退回简单模型”。可确认的是不同版本的外观及反馈，不是三十秒无剪辑完成全部制作。

| 可见的返工 | 可迁移的方法 | 不应过度推断 |
| --- | --- | --- |
| 神龛由简单圆台/柱体，变为石基层级、独立柱托、符纹及局部苔附着 | 保留大轮廓后，细化有结构职责的部件；环境痕迹有位置与方向 | 不把“更多细节”翻译为所有石面统一加面、加缝、加苔或加大倒角 |
| 鱼摊被指出太块状、看不出卖什么；随后出现分板柜体、支架、鱼盘和营业道具 | 先让用途与结构可读，再对仍不足的鱼表面补纹理 | 作者明确未确定纳入游戏；它不是已发布鱼摊的实景证明，红白棚也不是工业屋面配方 |
| 灌木先返工不合风格的叶形，再要求轻微交互，最后纠正漂浮果实 | 主体轮廓、叶簇层次、附属物落点分别检查；不能只凭综合色彩判断自然 | 画面未核实完整 UV、贴图/normal、实例分布或交互实现，静帧不能证明声音与摆幅 |

最适合迁移的是**可诊断的反馈方式**：“这条边承担什么、物体如何固定、入口接到哪里、近看才出现什么”。作者工具/模型名称和“整个过程”是来源描述；并列代码窗口、Normal 栏目或成品折光不能证明未显示的脚本、节点和参数。

### 环境也是验证的一部分，但不能一次改变所有变量

神龛有明确的 Blender 与 `in game` 标签，并展示同物体在白天、夕照、夜间的差别。鱼摊在后续版本加入沙地、光束外观和环境小物，构图与光照也改变。因此可借鉴“回到环境检查”，不能把跨版本观感差异全部归功于新增贴图。

本项目继续固定白天。先锁定机位、屏幕覆盖和日光检查结构，再检查深灰蓝旧漆与锈区，最后只针对已识别问题比较填充或投影。不要把工作视图的白色、夜间近黑石面或夕照橙红屋面误当材质本色。

## 对现有修船厂的执行顺序

本轮完成研究，下列是用于下一轮制作的具体顺序，尚未修改模型。沿用 B 厂房 + A 凹槽/维修船/石阶，深灰蓝、旧漆和明显锈蚀继续保留。

1. **先检查一条岸上工作路线。** 从岸上入口到厂门、坞侧工作面，再到临水检修位置，核对高度与方向。原截图没有显示所有入口，先查实际装配再处理可见断点；区分干地搬运与前梯临水检修用途。
2. **以一个接岸样区建立三种职责。** 岸側连续地面负责通路，门前/台面过渡负责高差，海侧挡墙与压顶负责重量。顶面铺地先读为工作面，接缝随后出现；保持维修槽、滑道和船道净空，不把整座坞削低或全边埋草。
3. **再整理旧铁皮的信息层次。** 深灰蓝旧漆大面 → 主要板搭接、泛水、门窗与框架 → 压型沟 → 螺钉与浅表面。重锈仍明显，但不让每条波谷重复同强度锈楔；残漆、锈层、裸钢的色块与反射分工。
4. **最后补少量有落点的环境细节。** 沙土积聚、低叶簇或道具集中在使用较少的局部，保留门前、台阶及工作台周边的净空。借鉴果实纠错检查附属物支点、接触和遮挡，不用装饰遮盖基础缺陷。
5. **同环境分项验证。** 固定白天与相机，分别看航行局部、厂门连接处、真正船侧低角度和侧背面。先确认结构/高差，再看材质与暗部；技术回归不替代用户视觉评价。所有网格、UV、Blender 材质/贴图操作仍通过本项目独立 Blender MCP。

下一轮最关键的可视目标是：**看得懂陆上怎样进入作业区、海侧为何需要厚墙，以及深色铁皮的大面怎样压住小细节。** 这比继续整栋提亮或均匀添加锈点更直接对应当前反馈。
