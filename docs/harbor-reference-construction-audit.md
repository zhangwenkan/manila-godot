## 1. 原作的“统一”，是有角色的统一

`level1` / `level2` 中，`Hut_Roof`、`Hut_Walls`、`Hut_WallS`、`Hut_Awning`、`Hut_Door`、`Hut_Net`、`Hut_Base` 等可见对象绑定 `M_Hut`。这一个材质的 BaseColor 为白色，实际绑定 2048² 的 `T_Hut_Albedo` 和 `T_Hut_Normal`，UV 缩放为 1、偏移为 0。

因此，房子里不同构件的色差和表面区别主要被分配在图集与 UV 中，而不是每个构件都换一套 shader。投影直接显示：

- **墙与框架分层。** 深色角柱、下缘和窗框把较亮的墙板包起来；板与板有小幅差异，板内也有宽缓的明暗与边缘变化。窗洞还有真正的空间开口。
- **屋顶有不同尺度的结构。** 粗檐口与屋脊形成外轮廓，细压条形成纵向节奏，屋面板形成横向分区。色差服从成片、成组的安排，不是所有碎块独立抽随机颜色。
- **边缘不是均匀白线。** 顶面、侧面、端面、搭接位置的颜色信息不同；在只显示 Albedo 时仍能读到线和面的区别。至于其中哪些来自手绘、哪些来自烘焙，现有材料不能唯一确定。
- **图集不是无缝木纹。** 它按构件表面打包，岛的尺寸与形状很多，细节和位置相关。不能截一段后无差别平铺到新房所有表面。

另一组 `HouseA` 建筑采用不同但兼容的组织方式：共用 4K Albedo / 2K Normal，分别有 `Plain`、`Paint`、`Trim`、`Accent`、`Shingle`、`Tile` 材质族。它能补充证明作者有意识地区分构件用途，但不能把这组可装修建筑的设置冒充参考视频里 `Hut` 的设置。

## 2. 当前货仓缺的不是纹理文件大小

最新 `coast_21_deep_timber` 已替换早期错误的桥图集窄条映射，使用独立 2K 木材图集。旧诊断中“仅约 25 像素宽的条带”不再是最新资产的问题。

现在的问题是 `coast_12_craft_structure.mcp.json` 的 `plank()` 将不同长度、宽度的构件都铺满同一个 488 × 232 像素的有效区域。长度变化后，木纹、节疤、裂隙的实际大小跟着改变；侧面还经常复用同样的整片纹理。

以三角面局部 UV 微分的两个奇异值之比衡量方向拉伸，1 表示两个方向的像素尺度相同。排除退化三角形后按三维表面积加权：

| 范围 | 拉伸比中位数 | 拉伸比 P90 |
| --- | ---: | ---: |
| 原作 `Hut_Walls` | 1.004 | 1.008 |
| 原作 `Hut_Roof` | 1.183 | 1.183 |
| 原作 `Hut_Door` | 1.000 | 1.001 |
| 当前货仓正面墙板外表面，不含倒角 | 4.560 | 6.868 |
| 当前全部木材，含梁柱和道具 | 4.267 | 13.744 |

原作 OBJ 的尺度和 UV 已与 Unity 原始 Mesh 对照；导出翻转 X，不改变面积与该比例。当前 GLB 按节点变换恢复位置后筛选正面墙板；筛选条件和统计代码均保存在证据目录。比例相同也不能自动证明纹理内容正确，该统计只用于定位映射失真。

原作墙与门的面密度中位数约 24 像素/资产单位，当前正面墙板约 597。原作平台约 56，说明其各类资产也不要求一个绝对统一值。这里未统一两个游戏的世界比例和最终屏幕覆盖，不能拿这些数值评比屏幕清晰度，更不能把 24 当作本项目的新规格；但它明确说明“更多贴图像素”没有解决当前问题。参考依靠可读的几何、合适的纹理内容及映射组织，而非无限加密细木纹。

最新木材基础颜色中，墙板约 `(128,103,82)`，屋面约 `(132,106,85)`，梁木约 `(106,84,65)`；墙和屋面过近，同组随机变化也已被压到很窄。大面积看到的仍是相似的连续柔软波纹。四类尺度没有分开：主体轮廓、构件分组、板材分缝、少量表面纹理。

## 3. 材质、光影、描边分别起什么作用

直接读取材质指针得到的绑定如下，不能用导出文本中列出的所有 shader 属性推断功能均已启用：

| 材质 | 实际颜色图 / 法线图 | Smoothness |
| --- | --- | ---: |
| `M_Hut` | 2048² / 2048² | 0.07 |
| `M_HutDock` | 2048² / 2048² | 0.07 |
| `M_Bridge` | 2048² / 2048² | 0.15 |
| `M_Crate` | 2048² / 1024² | 0.15 |
| `M_Boats` | 4096² / 2048² | 0.20 |
| `HouseA` 材质族 | 4096² / 2048² | 屋面板 0.12、原木 0.16、瓦 0.18、漆面 0.20、边框 0.22、点缀 0.24 |

这些被检查的材质没有绑定 Mask/AO 贴图，`_MainTex` 是颜色图的重复引用。先前拆解报告中“统一使用 Albedo + Normal + Mask”的概括不适用于这些对象。颜色图内部可能已有接缝、局部遮蔽等明暗，不能由“无独立 AO 图”推断“完全无烘焙明暗”。

`M_Hut` 的 shader 解析名称为 `HDRP/Lit`，法线关键词确有启用。当前 Godot 木材粗糙度为 0.91，本来就接近哑光木材方向，继续增加粗糙度不会补出构件层次；也不能跨引擎照抄某个法线强度便认为一致。参考 Normal 导出存在通道打包，不能直接把红粉色 RGB 当作普通法线判断。

光影的证据：相关可见网格投射并接收阴影，LightmapIndex 为 65535，未绑定烘焙 lightmap。`BeachVolumeProfile` 包含 Exposure、Tonemapping、ColorAdjustments、WhiteBalance、ShadowsMidtonesHighlights、ScreenSpaceAmbientOcclusion、ContactShadows、HDShadowSettings 等组件。**这里只核实了组件引用，没有解码各项参数和运行时开启情况。** 太阳序列化设置为白色、启用 5900K 色温、100000 强度、软阴影，可能被 DayNight 逻辑覆盖，不能说参考截图恰好用了这些数值，也不能直接换算成 Godot energy。

描边也找到了实质绑定：`level1` 的 `Ink Outline Pass` / `CustomPassVolume` 内包含名为 `Ink Outline` 的 `FullScreenCustomPass`，引用 `sharedassets1.assets` pathID 55，即 `M_InkOutline`，shader 为 `FullScreen/BeachInkOutline`。序列化参数有 Thickness 1.5、Opacity 0.85、DepthThreshold 0.6、NormalThreshold 0.5。

但编译 shader 导出失败，尚不能确认其逐像素逻辑、选区条件及截图时的实际作用范围。不能从这个发现直接给本项目全场加黑描边。前面的无描边投影已能显示参考的结构层次，说明描边不是唯一来源。原作 `Hut_Edge` 没有 MeshRenderer，只有 MeshFilter / MeshCollider，不能把它当作可见描边壳。

另外，原作墙、屋顶、网与基座含灰度顶点颜色；目前没有证据证明这些颜色被当前 `HDRP/Lit` 路径读取。不能宣称“开启顶点 AO”就是原作秘诀。

## 4. 箱、绳、网为何配套

它们并非全部共用一套房屋材质。场景绑定显示木箱有 `M_Crate`，`RopeCoil` 使用 `M_Harbour`，小屋桶使用 `M_HutInside`，而 `Hut_Net` 使用 `M_Hut`。之前把桶放在小屋外图集上推断其内容会造成误判。

和谐首先来自物件尺度、用途和表面语言一致：木箱角框与板面有从属，绳盘有盘绕与末端，网有固定点和垂坠，端面、铁箍、麻纤维各自不同。原作网和绳有真实几何轮廓，靠法线无法替代。参考实景中货物靠门、绳靠系船位置、网挂平台边，通行区域留空；不是每种道具都均匀堆满。

当前已有分板箱、桶、绳网，但全部细节的存在不等于整体质量成立。首先需要让框架与板面相互衬托，统一纹理物理尺度；绳和网的细节密度也应服从总览可读性，不能靠线越密越细制造精致感。

## 5. 下一轮可执行的改法与检查门槛

仍只处理货仓样区，所有模型和 UV 修改经隔离 Blender MCP，保持唯一根工程与唯一入口。

1. **先修一个“檐口—角柱—墙板—门框”的完整转角。** 保持深大地色，建立较深且较粗的承重框架、中间明度的墙板、独立的屋面大块面、少量较浅的磨损边和端面。组间差异大于组内变化。框架在总览缩小时仍应可见。
2. **重排构件表面的映射。** 长面顺纹，端面单独，侧面按尺寸分配；采用按物理长度裁切的共享条带或按实际尺寸展开，不再每块自动填满同样矩形。以墙板、长梁、短箱板三个长度同时检查节疤和裂隙尺度。
3. **重做板面内容。** 先有干净的中尺度明暗和有限的边缘变化，再加稀疏顺纹、少量裂隙与节疤。搭接、暗缝、倒角亮面分别承担不同线宽；减少等间距波纹和满边统一亮线。固定接触位置可有克制的局部遮蔽，动态太阳投影不能画死进颜色贴图。
4. **整理屋面节奏和物件层级。** 强化真实屋檐厚度、覆盖关系与少量连续压条；避免全屋等宽碎板同样密集。箱体先读到框和面，再读到钉；绳网先读到受力与悬垂，再读到纤维。
5. **在现有固定白天检验。** 同一入口检查总览、近参考俯角、门窗近景、船侧低角度和背面。确认阴影显出厚度，暗部仍有材质，不出现发白边或脏黑缝。先检验资产主次，再评估是否需要微调光照或描边。

通过条件：缩小看能读到屋顶、墙与骨架；放大看纹理尺度一致、有清楚的接缝及端面，且没有一层均匀细噪声覆盖全部表面；低角度有真实厚度和凹陷。最终仍需要用户视觉认可，不能以面数、截图数量或测试通过替代。

用户认为比最初版本明显改善，但指出货仓、船、桥共同存在过于光滑、像 3D 打印物件的问题。这是下一层质量问题，不代表前轮货仓已经验收，也不授权恢复全港扩建。本轮只处理这些已有木材资产，所有模型、贴图及 Blender 材质操作仍通过独立 PID 56488 / MCP 9878 的实际会话完成。

### 判断与实施

- 船、桥原运行时 roughness 已分别为 0.90、0.92；它们原有整张法线图倾角 P90 约 1.59°，货仓为 0.32°。这些统计包含图集空区与留边，只能支持“原凹凸很弱”，不能代替画面判断。旧木材缺少局部粗糙度图，颜色中的连续条带也强化了光滑印纹感。
- 货仓木材沿物理尺寸图集增加断续、疏密不同的纵向纤维沟、少量短端裂与局部摩擦区。保留深框架、中间墙板、较浅平台的层次；缩小连续宽条纹的反差。高度场独立于颜色信息，不将每条色纹全部压成立体纹路。
- 船与工作桥沿原有 UV / 构件方向制作同类表面，保留逐构件原本色值关系，减弱部分连续波纹；船舷、地板、桥板的纤维按实际长度分布。到港平台共享工作桥材质，破桥不在本轮修改范围。
- 新增三张粗糙度图：`boat_wood_roughness.png`、`pier_wood_roughness.png`、`coast/HarborCraft_Timber_roughness.png`。局部摩擦与较干燥区域具有不同反光响应；Godot 对有粗糙度贴图的船桥将标量系数设为 1，避免再次将贴图绝对值乘低。保留既有金属度、色彩方向、固定白天与水体参数。
- 少量板材在原顶点上有毫米级变形和局部角部磨损；额外细分已经撤去，平台甲板恢复本轮前的拓扑。最终四个 GLB 的三角面数均与本轮前相同：货仓 68,752、船 8,244、工作桥 12,864、到港平台 15,832。货仓仍为 16 个合并导出网格、770 个编辑构件。

### 视觉边界与过程纠正

实际画面中连续印纹感有所减弱，近处能读到更多断续纤维及局部裂隙，远处仍保持原有色块关系。变化较克制；尤其船舷的连续轮廓、板端与部分柱帽仍偏规整，不能宣称“打印模型感”已经消除。不要靠进一步统一加深裂纹、添加黑噪点或整体提亮解决这些剩余问题。当前仍待用户视觉判断。

本轮中间失败的真实原因已经记录：一次导出未取消到港平台隐藏造成空 GLB，随后修复并核对 `LandingDeck` 存在；一次批量恢复因 Blender 库加载返回对象名列表被原地替换而失败，改为独立名称元组后成功恢复 160 个原网格；一次临时图像衰减未落盘，随后由最终表面重绘覆盖。最终资产以本节证据为准，阶段 payload 不能按编号无脑重放。

更正早期进度判断：空 GLB 是导出错误，并非缓存；42 恢复失败后曾执行 38 保存，所以“操作没有保存”也不准确。另一次回归前两张截图为 1600×900、后续变为 3200×1800，触发尺寸检查失败，未查明切换原因，不将该次计为通过。最终这次尺寸正确。

本轮前备份为 `captures/surface_before_20261109_213235`；当前可编辑源为 `source/harbor_coast_mcp.blend`，其中包含本轮船、桥和平台。旧 `harbor_art_mcp.blend` 不是新表面的源文件。最终表面调用关系为 34 定义基础函数 → 49 定义断续纤维 → 50 货仓 → 35 船 → 36 桥 → 38 安全导出。49 依赖干净的 34 基础函数，不能重复包装；37、40、42、45 不再运行，48 是已被最终重绘覆盖的中间尝试。47 完成原网格恢复，44 恢复平台甲板，最终导出统计已核对。最终船桥 normal scale 为 0.9，不沿用中间 .72/.82 的说明。
