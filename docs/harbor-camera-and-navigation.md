## 产品前提：策略游戏的三维美术表现

用户进一步明确：这是天然可以用 2D 表达的策略桌游，使用 3D 是为了更好地表现美术、空间、环境与微动画。用户曾在 2D、3D、像素化及横向推进镜头之间权衡；这个背景不能被误读成要做 RPG、角色探索或模拟完整可游览世界。现行项目仍沿用已确认的非像素风 3D 美术方向，提及历史选择不构成重新改风格的指令。

场景没有承担玩家视点的主角。三艘船只在航行阶段共同成为主要关注对象，玩家决策时可以由当前相关的建筑、作业区或局部场景承担视觉重点。镜头由游戏阶段、事件与画面设计安排，不从角色视角、角色位置或玩家编号推导。未来工人等环境角色也不因此获得主角跟随相机。

策略信息需要清楚、稳定、可比较，不应因为好看的局部镜头而隐去玩家必需的信息，或强迫玩家移动镜头寻找岗位。全局信息与派遣由既定沙盘 UI 方向承担；局部 3D 负责呈现空间、动作与结果。展示顺序和用时不能改变规则推进。

镜头以稳定、可读和少打断决策为优先，只在航行、事件或必要的关注切换时运动。扩大场景是为了分开局部构图，不等于增加探索内容、自由镜头、角色寻路或延长每次航行动画；适当调整表现速度，让等待时间适合策略回合节奏。

## 已明确的体验要求

| 层面 | 用户要求 | 验证重点 |
| --- | --- | --- |
| 局部范围 | 每屏只展示当前附近的一片港口，不需要同时看见所有建筑或元素。起点只见起点附近，终点不应出现在起点画面。 | 起点、中段、末段必须有明显不同的空间内容，不能只对全景略微裁切。 |
| 主次与尺度 | 船是航行阶段的主体，货物、小兵及附近有效环境有可读尺寸；决策阶段可展示当前相关建筑或作业区。分辨率不是扩大局部感的手段。 | 不能为塞下远处地标、整栋建筑或全船队而不断拉远，也不能把某条船当成全程唯一主角。 |
| 航行观察 | 船移动时镜头跟随，允许位置、观察方向、俯角、距离等随航段变化。斜俯视只是可用构图之一。 | 看得出船在通过环境；相机变化连贯，有明确关注对象，避免突然在某个整数刻度转头。 |
| 决策停驻 | 每次行动/决策前，画面应落在适合当前局部的稳定观看角度。船、岸边工作区、自然环境和微动画共同组成画面。 | 停船后的画面应独立成立，不能只是跟拍途中随便冻结的一帧。 |
| 镜头控制权 | 玩家无需自由旋转镜头，游戏可以主动安排和调整机位。 | “玩家不能自由操作”不得再误写成“相机朝向永久锁死”。 |
| 建筑展示 | 修船厂、保险公司、竞拍等应能展示临水作业面/正面及有用细节，而不是长期只看侧背面和屋顶。 | 同时调整机位、建筑摆向、岸线与航线；用合适角度解决屋顶抢画面，不能仅缩小建筑。 |
| 终点构图 | 到港也只需要舒适的局部画面，重点是船、有效码头构件、小兵/互动位置与微动画。 | 不要求整个终点建筑群完整进入画面。 |

## 上一版为什么偏离

- `environment/harbor_layout.gd` 的 STEP 为 1.4，0 到 13 总计 18.2 米；注释中的船壳约 4.7 米长，整段规则航道不到四个船长，功能区挤在同一小范围。
- `fleet/fleet_camera.gd::_update_local_harbor()` 使用三船平均 Z、固定偏移 `(18,28,36)` 与 FOV 26°，并为所有船体包络后退。这会把镜头重新拉成全景，不能作为新的局部构图策略。
- 相机目标 X=-0.4，加偏移后相机 X≈17.6；主要临水建筑在 X≈10–11 且正面朝海。机位落到岸侧，长期看不到临水正面，是布局与镜头没有配合的问题。
- 139 项局部检查中的“所有船同时可见”只证明旧约束成立；不能证明用户要求的局部体验成立。271 项原回归也不构成此视觉方向的通过。
- 上一版“左侧留海优于连陆地”的判断只针对紧凑场景和旧机位；新局部布局应逐段重看，不把整条左岸限制为全海或全陆地。

## 建议的实现方向（尚未验证或定案）

保留当前分辨率及船、人物、建筑的正常相对尺度，优先拉长实际航程并拉开功能区，缩小每次拍摄的世界范围。可从现有规则航道长度的约 3–4 倍起做占位比较，数字只是初始试验参数，不是必须建设多大地图的承诺。世界范围增大不要求全区域同时精修或渲染；空间增加也不直接等于相同倍数的帧耗时。

先安排少量关键局部，例如起航水湾、沿岸作业区、海盗附近、到港前沿；再共同调整连接它们的岸线、三条航线、建筑摆向与相机观察路径。每处先确定船在前/中景、建筑可读面在中/后景的静止构图，然后检验它们之间的运动。

优先比较宽缓的弧形或很浅的 S 形，不直接认定必须大扇形或强 S 弯。船的曲线和相机的观察路径分别设计：弯道提供转向理由，但直线段也可以平滑偏向附近建筑；相机不必刚性绑定船头朝向，避免船每次转弯都带来左右摆头。镜头方位、俯角和距离可共同变化，变化幅度由画面验证决定。

建筑临水正面可以随海湾朝向形成不同角度，镜头从合适的水面一侧观察船和作业区；不要求所有建筑平行朝左，也不靠一只环绕全港的相机去补救所有朝向。已有精修资产优先重新装配，是否改模型另按实际问题与 Blender MCP 约束处理。

先保持透视投影，通过距离、俯角和适度焦距调整比较构图。2.5D/等距感是一种视觉候选，不等于必须在航行时切正交、停船时切透视；暂不把频繁切换投影作为前提。

## 灯塔进入航行水域的补充判断

用户补充希望灯塔更深入三船航行的水域，让引航的 +1/+2/-1/-2 表现更容易与船建立联系，也让局部镜头有机会展示海上灯塔；同时明确不得妨碍航行，具体布局交由设计判断。这是功能地标位置的建议，不要求灯塔永远同屏或放在某条船的实际运动中心线上。

采用方向：下一轮空间原型优先把灯塔作为航道区域内部的海上地标，在两条独立航线之间预留一处局部放宽的水域，安排小岩礁/紧凑塔基；三条航线保持各自顺序与安全净空，从旁经过。灯塔附近形成一幅能同时表现船与塔的局部构图，放在哪个航段随新路线与机位验证，不能为安放它先强制定死大扇形或 S 形。

现有直线中心间距为 3.3 米，船宽约 1.8 米，船壳之间理论净距仅约 1.5 米，尚未计入转弯与浮动余量。只读检查现有灯塔 GLB：岛礁/平台横向占地约 4.3 米，因此不能直接把当前整座灯塔平移进旧航道缝隙。应与场景尺度、航道局部间隔一起调整；需要改底座模型时仍经 Blender MCP 制作。

必须分别验证船体运动净空与屏幕遮挡：岛礁/平台不得占用船体经过范围，塔身也不能在镜头转向或停驻后遮住正在关注的船、小兵及关键动作。优先在展示灯塔的机位里让塔在船的侧后方，并检查正常前进、引航后退与不同船距。空间位置合适不自动证明画面无遮挡。

引航表现建议使用灯塔定向点亮/光束指向所选船，配合船上简短的带正负号步数提示，以及船沿自己航道的实际前进或后退；灯光负责交代动作来源，符号与位移负责清楚表达方向。固定白天仍需可辨，不把白天光束效果视作已经解决或已实现。

引航在第三次投骰前发生，届时各船可能相距很远。灯塔位置或可见光束范围不能额外增加“必须靠近灯塔才能引航”的规则；必要时可用简短灯塔动作衔接目标船局部，不为让塔与所有目标同屏重新拉成全景。大小引航两处岗位及原规则移动选择保留，当前仅记录设计方向，运行灯塔位置与玩法尚未修改。

## 航行与决策的衔接

建议流程：稳定的局部决策构图 → 航行开始后平滑进入跟随 → 随航段逐渐调整观察方向/高度/距离 → 停船前减速收拢构图 → 下一次决策时稳定停驻。水、旗、灯、吊货等环境动画仍可持续。

骰点会使船停在不同进度，不能只给四个漂亮固定点拍照，而其他停止位置失效。以航程连续参数生成合适的停驻构图；同一局部有多个玩家轮流决策时不必每换一人就切镜头。具体任务或事件需要强调另一区域时，才有理由转移关注。

镜头运动由当前航行或事件的关注对象决定；桌游玩家会在不同船及不同岗位投资，不能自行假设“一位玩家永久对应一艘船”。规则状态的推进、同掷骰抵港次序、岗位归属、收益与镜头动画时长分开处理。

## 三船分散时的取舍

用户本轮明确不要求所有建筑同屏，尚未明确三艘船在任意距离下是否必须同屏。不能擅自把允许部分船离屏写成已经获确认的需求。

建议：船靠近时用局部船队构图；分散到跨越多个局部时优先保持主体尺度，通过适当切换关注对象或分段展示航行解释另外的船，而不是无限拉远。关注顺序、同时或分段展示、画外进度提示仍是待验证的设计选择；不能悄悄遗漏某艘船的移动和到港结果。既定沙盘 UI 第一方案承担全局状态，当前仍只记录，不制作。

## 独立航线与原规则不变的边界

三条曲线应围绕共同走向组织，检查所有正常可见航段的船体净空与相邻曲线关系，包括引航后退；不能只是中心线不相交。弧度或实际路径长度差异不改变骰子格数与到港条件，也不以动画先播完决定抵港次序。

海盗对应 13 号位；大小领航可前进或后退。到港仍按原规则停到实体 A/B/C，即使最右船先到也实际停 A。用户允许淡黑/到港小动画省略从航道出口到指定泊位的横向调度；当前 0.75 秒淡黑为临时验证实现，最终表现未选定。

全局查看与派遣的第一方案仍是独立交互式微缩 3D 沙盘菜单，保留 2D 插画与实时状态。它与港口共用规则状态，可采用自己的比例和布局，不把主场景抬高来代替。此轮不展开该 UI。

## 下一版应提供的验证证据

1. 起航的局部静帧：船具有足够尺度，只有起点附近环境，终点码头不在画面内。
2. 沿岸的局部静帧：能读到修船厂或保险等区域的临水正面、工作面及附近环境，船仍为主体。
3. 临近海盗/终点的不同局部静帧：内容与起点明显不同，终点不为完整展示而把船缩小。
4. 一段连续的实际航行：同时看到船沿独立航道移动、环境经过、镜头平滑变换以及停驻收稳；不能只交不相连的静态机位。
5. 不同骰点、船距、混合到港与领航前后移动的情况，分别验证关注对象尺度、必要信息、画面遮挡和路线净空。
6. 验收重点是局部体验与构图，自动包络/碰撞/规则检查只能辅助，不能取代实际看图与用户评价。
