## 专项技术检查

1. 找到唯一新终点实例且可见；源资源指向本轮 GLB，确认目标简单房屋组件已从运行 coast 导出移除。该移除证明需源组件清单和导出报告，不能只凭相机看不到房子。
2. 对新终点 AABB 各角进行有效前方／屏幕边界检查，确保单体整图没有裁塔顶、吊架或底部。背面和连接图单独按目标构件范围检查。
3. 临时隐藏的 `Node3D` 逐项恢复，再执行物理查询及到港。仅改 `visible` 不代表关闭碰撞；技术检查应在完整默认碰撞集合中运行。
4. 用真实规则执行右船先到 A 和三船全部到港：起始进度 `[0,3,13]`／骰子`[6,1,1]`，及起始`[13,13,13]`／骰子`[1,6,3]`；使用现有 `_start_parallel_sailing`、`simulate` 和到港淡黑逻辑，不直接更改泊位状态来冒充玩法验证。
5. 最终 A/B/C 对每船使用当前全船扫掠盒，collision mask 4、margin 0.06，确认新建筑／平台／吊货没有侵入；再检查船位与 `state.world_position` 一致，已到港船后续掷骰保持不动。
6. 正常到港镜头下检查三船中心／船头／船尾视线不被新增终点遮挡；船全包围框需留视窗边界。对手动全泊位图同样检查三船完整可见。
7. 新资产按当前 `reference_coast.gd` 生成静态相机碰撞；如有旗布／吊货活动部件，不能把会动细件烘焙为固定碰撞。静态主体碰撞和桥／甲板碰撞保留。

专项只报告实际执行的检查数，默认 `visual_accepted=false`；图像通过不等于艺术验收。即使专项技术通过，仍须最终完整 `rebuild --background`：当前包含开场三船、路线0..13.12扫掠、不同进度航道分离、66段相机检查、7组真实航行动画、暂停、真实A/B/C、已泊船保持、反向播放、船选择和受控相机检查。完整33图只是本轮开始时的数量；若主代理明确增加终点图，则按真实输出数量记录，不硬编码33。
